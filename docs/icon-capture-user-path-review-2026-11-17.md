# 用户实际收藏无 Logo：独立复核

## 用户补充与通用修订范围

用户补充失败地址为 https://www.qianwen.com/ 和 https://chatgpt.com/，并明确要求按这类网站机制统一改进，不能只针对两个域名硬编码。以下补充优先于旧规格中“一律不考虑跨源图标”的产品规则，但保留最小权限、SSRF、类型/字节/时间预算与私有媒体要求。

### 本轮实际网站读取与现有函数复现

- 千问当前公开HTML声明两张 `rel=shortcut icon` PNG，位于 `https://img.alicdn.com/`，以 media 区分浅色/深色。现有 buildIconCandidates 因非同源全部过滤；留下的同源 `/favicon.ico` 本轮返回404。此为明确的候选获取缺口，不是ICO大小问题。应优先匹配当前配色的候选，保存适合工作台浅色背景的安全栅格版本；不能任意拿第一张深色背景专用图。
- ChatGPT当前公开HTML提供同源SVG favicon、48px PNG及180px apple-touch PNG。现有函数会排除SVG但保留两个PNG；48px PNG本轮真实GET为200、image/png且有正确PNG魔数。服务端命令行请求成功不证明用户浏览器授权/网络成功，不应把ChatGPT失败直接归因于SVG或跨域；仍需同次用户操作的错误码/时序证据。
- 独立延迟复现已确认2秒保存期限会丢弃2.1秒才ready的图标；域名无关，必须作为通用缺陷修复。

网页声明会变化，开发前重新读取实际页面。不得把本轮哈希文件名固化在产品代码，也不得用站名查一个内置品牌图掩盖采集失败。

### 通用能力与分层处理

1. 候选发现：从用户调用扩展的真实页面读取有限白名单元数据，收集tab favicon、rel icon、apple-touch-icon，保留mime/sizes/media、完整绝对URL与来源；规范化相对路径，去重后按支持格式、实际可解码尺寸、当前主题排序。site manifest图标可作为后续有界能力，不为本轮无限爬资源。没有元数据时再尝试默认favicon路径。
2. 同源图片：用当前用户动作的最小授权，支持PNG/WebP/JPEG及已验证ICO等；候选错误要继续尝试，不能首个失败便宣告整个图标不存在。
3. 页面声明的公共CDN：不能一概过滤，也不能扩为任意URL抓取。优先用现有后端安全抓取作显式收藏后的自动兜底：后端重新读取已归属站点的公开页面，仅允许其声明的图标候选；每个URL/每跳DNS和重定向独立校验公网地址，拒绝内网、凭据、危险协议和不支持端口，限制候选数/跳数/字节/总时间。不附带网站Cookie、用户Bearer、Referer或私密query。设备不能借此传任意远程URL当抓取器。若需要客户端额外origin权限，必须是明确候选origin的用户授权，不申请全站常驻权限，不让取消授权阻止文字收藏。
4. SVG优先站点：先找页面声明的安全栅格替代（ChatGPT即有PNG），不能看见SVG便直接回退字母。SVG-only确有需求时采用经过验证的隔离栅格化路径，限制复杂度/像素/时间并禁用脚本、外链、嵌入HTML、远程字体与网络访问；若暂无法安全完成则明确列为不支持，不放开原始SVG执行或直接展示。不要为修这两个站点而引入未经审查的SVG解析器。
5. 慢请求与popup生命周期：文字先入库，图标获取/兜底/上传是独立持久化任务，关闭popup仍继续，失败有限退避，浏览器重启可恢复。不能仅把保存等待从2秒加到5秒，不能要求用户等ready再收藏。
6. 正确匹配与更新：任务绑定用户、完整server origin、capture ID、site/endpoint版本与来源；只给本次授权允许更新的缺图或明确更新项写入，已存在自定义/较新图不能被迟到任务覆盖。重试不新增网站、不重复写备注；跨账号任务不转投。已有字母回退收藏应可用相同新能力补图，不只支持今后新收藏。
7. 诊断：区分候选为空、跨源候选待兜底、权限拒绝、HTTP错误、格式不支持、解码失败、超预算、获取中、待上传及上传失败。保留capture/task ID、候选host、类型、大小、耗时和稳定错误码，不记录token、页面正文或完整敏感地址。仅素材已确认或明确终态降级后给出准确结果。

## 当前证据

用户反馈：agent测试收藏的网站Logo正常，但自己动手收藏时没有获取到。

本轮核对磁盘安装目录 `C:/Users/无名/Downloads/website-workspace-extension` 的全部打包文件与1.4.0 ZIP一致。仅能证明文件一致，不等于原浏览器运行时已重载；仍需核实popup实际版本。

已复现时序缺陷：

- 图标采集在 site-icon.js 有最多5秒墙钟预算。
- automatic-assets.js 的 waitForAutomaticAssets 在提交时只等2秒。
- popup.js 在提交时锁定素材结果并使迟到回调失效。
- persistAutomaticAssets 只把 ready 图标存入Blob/上传任务；unavailable没有待获取任务。
- 因此用户快速点击收藏时，尚在采集的图标超时后永久缺失；文字保存成功会让用户误以为所有工作会继续自动完成。

本轮通过现有真实等待/持久化函数，注入立即就绪截图与2100ms后成功的图标，输出：

```text
save elapsed ms: 2009
icon status: unavailable
queued icon: false
persisted: [preview]
late task result: ready
queued icon still: false
```

这是受控延迟复现，不是实体浏览器/该用户站点网络实测。它证明现有架构对快点收藏存在确定丢图路径，不能把新代码测试成功或图标源预算扩大视为该问题已解决。

## 修复目标

保留文字收藏即时响应，把“图标尚未取得”作为可恢复且持久化的任务，而不是永久取消附件。不要让用户等待“图标已就绪”才可收藏，更不能要求每次收藏后手动修复。

图标采集任务应在文字提交前登记稳定任务ID，绑定 server origin、用户、capture ID、目标URL与是否有更新许可。popup关闭后任务仍可执行/恢复。图标结果到达后通过独立幂等提交关联站点；如果站点来源发生改变、用户改图或取消，拒绝旧结果覆盖。不能借着任务异步化扩大权限、保留原始整页内容或给设备读取私密字段。

实施agent可选择现有安全服务端favicon能力作为公网缺图自动兜底，或把浏览器已授权采集搬入具有正确权限/生命周期的后台执行路径；需要说明当前activeTab授权何时存在以及浏览器后台解码支持。私网和身份变化不得转给公网服务器抓取。

任务状态至少包含 pending_acquisition、acquiring、ready_to_upload、complete、retryable_failure、unsupported、cancelled；显示“网站已入库，图标获取中/稍后重试”，仅真实终态才显示“资料和素材已确认”。重复收藏须仍显式确认图标更新，不自动覆盖已有图标。

别把5秒预算改为无限等待；采集预算超限应有限退避或安全兜底。一个候选失败不应该使其余有效候选失去全部机会；候选过滤、真实请求错误和解码失败需保留有用诊断，不泄露token或完整私密URL。

## 验收

1. 冷网络/首次访问：打开popup立刻点收藏，图标在2.1秒、4秒后到达均最终上传，文字不阻塞。
2. 素材未完成时关闭popup、重新加载扩展、完整浏览器重启，已登记任务保留或明确恢复，不丢。
3. 图标请求失败/超时/候选跨源无权限/解码失败，反馈具体且可恢复，不假报全完成。
4. 切换账号/服务器、撤销设备、重复提交和多窗口，任务不转投、不重复写、不覆盖较新图。
5. 用户原本失败的真实站点，从工具栏快速收藏到卡片Logo显示形成同一capture ID的完整证据；不能等待ready后再点击替代。
6. 更新ZIP/哈希/安装目录/运行时，保留当前账号、队列、备注分类和截图；本机测试，不部署云端。

本轮未替用户点击收藏或改变已有资料；待用户提供地址/版本/提示后，还需检查是否叠加旧运行时、跨源候选或重复收藏未选择图标更新等问题。
