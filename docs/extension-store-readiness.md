## 1. 为什么要正式商店渠道

阶段 A 已确认：未打包（ZIP「加载已解压的扩展程序」）必须开启 Edge 开发人员模式；Edge 重启可能把该开关关掉并禁用未打包扩展（禁用原因 `UNSUPPORTED_DEVELOPER_EXTENSION`），表现为扩展消失或「已停用」。这是分发环境约束，不是入口业务代码缺陷，也无法靠改代码或改浏览器受保护偏好/企业策略绕过（本轮禁止这么做）。正式长期使用应发布到 Microsoft Edge Add-ons（Chrome 另发官方商店），由商店负责签名、更新与启用。

- 官方依据：[Edge 侧载说明](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading)、[Edge 托管/更新渠道](https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/hosting-and-updating)。
- 站内「安装正式扩展」入口必须指向**真实已发布**的商店条目；商店未发布时不得制造链接或宣称已解决安装稳定性。当前 ZIP 下载入口保留为「开发测试渠道」，明确标注需开发者模式与正常重新加载。

## 2. 待用户准备的资料（本轮不代办）

1. Microsoft Edge Add-ons 开发者账号（注册、条款接受、付费/身份验证）。
2. 商店列表文案：名称、简介、分类、截图、隐私政策 URL；说明扩展读取当前页标题/简介/截图/图标、只发往用户自己配置的工作台 origin、不上传页面正文、设备凭据只存本机。
3. 权限理由（逐项，供审核）：
   - `activeTab`：用户点工具栏/快捷键时，短窗口读取当前活动标签页元数据与截图；不是常驻站点访问。
   - `scripting`：仅在用户主动调用时读取页面 `<meta>`/`<link rel=icon>` 与同源栅格图标；不注入常驻内容脚本。
   - `storage`：设备配对配置、显示偏好；业务任务在 IndexedDB 单一 Outbox。
   - `alarms`：MV3 worker 终止后由周期事件恢复持久化任务；不保活、不用 debugger/CDP。
   - `bookmarks`（可选）：仅用户明确授权后的书签导入预览。
   - `https://*/*`、`http://*/*`（可选 host 权限）：仅用户主动配对时申请其作用到自己配置的工作台 origin；公网 HTTPS、回环仅本机开发。
4. 隐私与数据处理说明：本地队列/Blob 不上传第三方；服务端公开图标补齐不使用 Cookie/Bearer/Referer、不接受任意 URL 代理；截图可能含登录内容，用户可关闭自动截图。
5. 商店包与本轮 ZIP 一致性核对流程（构建脚本 `scripts/build_extension.py` 产出不可变 ZIP + SHA-256 + 清单）。

## 3. 商店扩展 ID 变化与本地数据（关键）

商店安装的扩展 ID 与未打包加载目录派生的 ID **不同**，因此不能承诺「浏览器本地队列自动继承」：

- 旧扩展（未打包）先联网同步完待提交任务，或提供**不含 token** 的、用户明确确认的导出；绝不把 Bearer/设备凭据写进任何导出包或商店包。本站内下载 ZIP 也不写入用户凭证。
- 新扩展（商店版）安装后重新配对同一工作台账号；配对后同账号的已确认收藏不受影响（服务端收藏按 owner 隔离）。
- 任务迁移是**独立可恢复**过程：先备份旧队列/任务表/Blob，在独立副本验证迁移（任务数、身份、Blob 摘要）后再写入带 `schemaVersion` 的新库；冲突/认证失效/拒绝任务不迁成自动可提交；失败保留旧数据可恢复、不清空旧存储。
- **不要先卸载旧版**：卸载会删除其本地队列与 IndexedDB；应先导出/同步，确认新扩展配对可用，再由用户自行决定是否移除旧加载目录。
