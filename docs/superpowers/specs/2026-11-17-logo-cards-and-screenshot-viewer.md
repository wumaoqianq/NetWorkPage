# Logo 主体卡片、独立截图查看与可调尺寸

日期：2026-11-17，Asia/Shanghai。状态：已实现并完成本机自动化与真实 Edge 验证；其他浏览器及完整实体升级流程未验收。

本规格覆盖 2026-11-16 中“卡片正文旁放截图缩略图”的规则；普通收藏直接入库、分类备注、自动采集、私有媒体与低内存部署要求保持有效。用户目标是：卡片通过网站 Logo 快速识别；截图需要时再清楚查看；卡片尺寸可按偏好调节，并随实际空间调整内容布局。

## 1. 先排查截图未展示，再调整入口

用户报告截图未展示，不得仅删掉缩略图掩盖问题。开发需在保留现有账号/收藏的前提下，通过用户授权的本机页面复现：

1. 插件捕获和本地 Blob 是否存在，收藏回执和附件上传是否分别完成。
2. 数据库 PreviewAsset、媒体文件、DTO `presentation.preview.present/fullUrl/revision` 是否一致。
3. 登录后的真实浏览器媒体请求状态、Content-Type、解码结果与 naturalWidth；401/403、404、损坏图、版本变化分别处理。
4. 检查 React 图片失败状态是否在 URL/revision 变化时重置：当前 SiteCard、SiteIcon、DetailPreview 使用本地失败标志，开发须验证失败后服务端换图是否能自动恢复，不允许旧失败永久遮住新图。
5. 区分“还没捕获”“本地待上传”“服务器已有图但浏览器读失败”，不要全部标成“没有截图”。

本轮已读当前源码：SiteCard 缩略图点击只是打开网站详情，并非直接看大图；DetailPreview 失败时禁用放大入口，未提供明确重试。这些是待调整的交互事实，不等于已确定用户图片故障根因。根因必须用真实请求和回归证据说明，不能凭截图文件存在就声称已修复。

## 2. 卡片结构与操作

```text
┌────────────────────────────┐
│ 置顶                     ⋯ │
│          [网站 Logo]        │
│          网站名称           │
│        example.com          │
│     备注或简介摘要……        │
│ [自定义分类]       [+2 标签] │
│ [查看截图]         [打开 ↗] │
└────────────────────────────┘
```

不再请求或展示截图缩略图，卡片主体由网站自己的 Logo 构成，不是工作台品牌 Logo。用户不需要先进入详情再找截图；每张有截图的卡片都有明确“查看截图”按钮，与“打开网站”并列。

点击 Logo、名称进入站内详情；点击“查看截图”直接打开截图查看器；点击“打开”沿用默认入口/多入口确认规则。三种动作不混淆，不把整张卡片设为外链；回收站“打开”替换为“查看资料”。菜单保留编辑、置顶、归档、回收站及更换素材等原功能。

Logo 区采用中性浅底、轻边界，不使用网站品牌色推导大面积背景。图片 `object-fit:contain`，保留透明与长宽比，不裁切宽 Logo、不拉伸 favicon；主图可视尺寸最多 64px，受管源图最大 128px 足够使用。首选已保存网站图标；无图/加载失败用稳定底色+网站首字母/首个汉字。通用占位不能冒充真实网站 Logo，也不能一律用本项目 Logo。

名称最长两行仅在大卡片出现；完整名称在详情和可访问名称中提供。地址默认只显示主机名，标准/大卡片有空间时可加路径，隐藏 query/hash 值，复制仍复制完整实际 URL。摘要优先个人备注，其次简介，搜索继续覆盖被隐藏的完整字段。

## 3. 查看截图按钮与查看器

### 3.1 按钮状态

| 真实状态 | 卡片按钮/提示 | 操作 |
| --- | --- | --- |
| preview.present=true | 查看截图 | 打开查看器并按需请求主图 |
| 服务端确认的处理状态 | 截图同步中（仅有真实状态时） | 可打开说明，不伪造百分比 |
| 没有服务端图片 | 暂无截图 | 可点，解释自动采集可能失败并提供扩展更新指引 |
| 已有图片但请求失败 | 卡片仍保留查看入口 | 在查看器显示加载错误和重试，不永久隐藏按钮 |
| 归档/回收站且仍有图 | 查看截图 | 仍按当前用户权限读取；不自动移除媒体 |

若网页不知道插件本机上传状态，就不能凭空显示“同步中”。可显示最近已知的服务端存在/不存在状态，恢复焦点或轻量刷新后更新。无图提示不可作为每张卡片的强警告；用低对比按钮即可。

### 3.2 查看器布局

桌面用独立 Dialog，宽度 `min(1120px, 94vw)`、最大高 92dvh；移动端采用全屏查看面板，顶部关闭与底部工具始终可达。复用 dialogStack，支持 Escape、焦点锁定和关闭后回到原卡片按钮。无须先渲染整个 SiteDetail，也不同时叠两个功能相同的弹层。

标题：“网站名称 · 页面截图”。副标题显示截图来源（当前页/用户确认的首页）、拍摄时间；来源 URL 可展开且隐藏默认 query/hash。不要用截图时间证明站点当前状态。

图片区使用同源鉴权的 fullUrl，加载时 skeleton/加载说明，成功后 `object-fit:contain` 显示完整画面，不用 cover 裁切。默认“适应窗口”；提供“100%原尺寸”和放大/缩小（50%–200%）及重置。超过面板尺寸时在图片区滚动/平移，弹层标题/按钮不跟着消失；手机支持触控滚动，优先避免自制手势劫持浏览器缩放。

截图分辨率只有 960×540 时，原尺寸可清楚看其已有细节，但放大不会产生新清晰度。显示“放大不增加原图清晰度”，不把尺寸放大称作高清增强。本轮不为解决可读性擅自提高上传配额、媒体规格或引入 AI 修复；如用户后续要求高清，另行评估客户端压缩、磁盘、备份和旧图兼容。

加载失败显示分类错误：登录过期→重新登录；文件不存在/损坏→“截图暂不可用”，可重试或用扩展更新；地址版本变化→重新读取该网站最新 preview 元信息。错误不退化成空白，不自动删除资产；重试不加任意 query 破坏 revision 校验。

关闭、换网站、切换账号时取消/忽略旧请求；切到不同 siteId/fullUrl/revision 时重置 loading/error/zoom。预览新图不能被旧 onError 回调覆盖。鉴权图片不改成公开静态链接，不把 bearer 放 URL，不创建跨用户共享缓存。

## 4. 卡片尺寸调节

网站列表工具栏增加“卡片大小”，位于网格/列表切换旁。默认标准。显示三档快捷按钮“紧凑 / 标准 / 宽松”，展开后可拖动滑杆微调目标宽度 200–340px，步长 20px，并提供“恢复默认”。键盘方向键可调，aria-valuetext 如“标准，目标宽度 260 像素”。

调节作用于当前账号的全部网站卡片，不提供单卡自由拖拽尺寸，避免参差不齐和难维护的布局。偏好保存为浏览器本地当前 origin+当前 userId 的 view preference，schemaVersion=1，不存入 Site 数据；演示模式独立键。刷新/重开保留，其他账号不继承；本期不承诺跨设备同步。存储失败本次仍生效，提示“本次已调整，浏览器未能保存偏好”，不抛异常阻断页面。

拖动实时预览但不把每个 input 事件写磁盘，不重新请求网站库、不重新挂载整个卡片列表、不重复请求图标。松手/键盘停止后保存；不会清空搜索、分类或当前滚动位置，不移动正在操作的菜单到屏幕外。

网格按可用内容宽度和目标宽度计算列数，实际卡片均分可用空间、同一行等高；不能简单 transform:scale、固定列数或让最后一张卡片自动扩成整行。使用 auto-fill 或等价列计算。间距紧凑 12px、标准/宽松 16px。若容器不足目标宽度，单列卡片填满可用宽，适配策略按实际宽度选择；不出现横向页面溢出。

列表模式不强制变成网格：控件禁用并提示“切换卡片视图后可调整”，保留最近的卡片偏好；切回网格恢复。手机保留调节入口，若实际宽度无法改变列数，说明“当前单列，尺寸设置将用于较宽窗口”，真实布局由容器规则决定，不假装总是能增减列数。

## 5. 按实际卡片宽度切换显示策略

以卡片容器宽度为依据（CSS container queries 或等价测量），不能只用 window 宽度，因为侧栏/浏览器缩放都会改变内容区。表中高度是正常内容的设计目标；200%缩放或长文本允许自然增长，禁止为卡高度裁掉操作按钮。

| 实际宽度 | 紧凑：<240px | 标准：240–299px | 宽松：≥300px |
| --- | --- | --- | --- |
| 正常目标高度 | 约 164px | 约 200px | 约 236px |
| Logo 视觉尺寸 | 36px | 48px | 64px |
| 内边距 | 12px | 14px | 16px |
| 网站名称 | 14px，一行 | 15px，一行 | 16px，最多两行 |
| 地址 | 主机名一行 | 主机名一行 | 主机名+可容纳的路径一行 |
| 摘要 | 隐藏，详情可读 | 一行 | 两行 |
| 分类/标签 | 分类一项，无标签文字 | 分类+标签数量 | 分类+最多两个标签，余量合并 |
| 查看截图/打开 | 明确文字，均保留 | 明确文字，均保留 | 明确文字，均保留 |
| 菜单与置顶 | 保留 | 保留 | 保留 |

手机触控与 coarse pointer 场景操作目标至少 44px，允许高度增加；桌面按钮视觉高 32px 并具备足够间距与清晰 focus。窄屏不把查看截图藏到菜单或只剩无人能懂的图标。标签、地址和摘要先让位，名称、Logo、截图入口与打开按钮始终保留。

文字大小只按档位轻微调整，不与滑杆同比缩小，最小字号不低于 12px。卡片背景白色，边框浅灰绿，圆角 12px，沿用当前绿色强调；hover 轻微加深边框，不以巨大阴影或弹跳强化点击。信息变少时保留对齐，勿把 Logo 区做成大片空白。

## 6. 数据与性能边界

卡片只需要图标 URL、preview.present 等轻量元数据；截图主图仅在查看时加载，禁止列表扫描每条 fullUrl 确认有没有图。图标继续 lazy loading，按批次渲染，不因拖滑杆对所有网站发图请求。

查看器以 siteId + preview revision 识别资源，不把 Site payload 的完整私有内容放本地视图偏好。图标/截图失败状态按资源版本重置，卡片大小不得写入服务器用户资料或引发 Site.version 变化。轮询更新媒体时不关闭查看器、不覆盖编辑表单；当前打开图片如已更新，显示“有新截图，点击刷新”，避免阅读中突然换图。

若采用新预览元数据接口，沿用现有 owner/session 鉴权与 CSRF，不让扩展设备凭证获得私人图片读取权限。无需扩展增加权限即可完成本次网页查看器与尺寸调节；若为修正采集缺陷改动扩展源码，才升级补丁版本并重建 ZIP/清单。

## 7. 开发顺序与验收

1. 先复现截图缺失：保存网络状态和实际数据关联，定位根因，新增回归；不得修改真实用户备注/收藏来构造测试。
2. 建立复用截图查看器及资源状态处理，卡片/详情均调用它；截图从卡片直接打开且全图不裁切。
3. 重构 Logo 主体卡片，去除内嵌截图缩略图和相应列表请求。
4. 增加尺寸控件、用户隔离偏好、容器响应策略；同步 grid/list、键盘及手机行为。
5. 验证正常图、无图、图标失败、截图 401/404/损坏、重试成功、失败后新 revision、切换 siteId 与账号、从归档/回收站查看。
6. 用至少 30 条合成数据，在 360/768/1280/1440/1920px 及 200%缩放下记录各档实际宽度、列数、高度；重点验证跨 239/240、299/300px 阈值不跳坏、按钮不遮挡、最后一行不拉伸。
7. 检查拖动不触发 API 写入、截图列表请求为零、查看一张才加载一张、正常更新图标错误状态恢复。搜索/分类/置顶排序、直接入库、已有队列及备份要求不回退。
8. 运行前端行为测试/构建，涉及后端或扩展则追加对应回归。真实 Edge 登录后验证“插件收藏→卡片 Logo→点击截图→全图显示→调尺寸→刷新保留”，不能只用 API 或 naturalWidth 冒充可读性验收。
9. 保留现有独立本机账号和收藏，构建并更新 http://127.0.0.1:4173/；不要新建空库、不要部署云端。报告根因、截图证据、实际测试结果与未实测项。

## 8. 可直接交接的提示词

请在当前项目实施本规格，完成而不是只写方案。用户新的决定是：网站 Logo 做卡片主体；截图通过卡片上的“查看截图”按钮直接清晰查看；卡片大小可调，按实际卡片容器大小切换信息展示策略。

先排查当前截图采集/上传/读取/展示链路，明确用户“截图未展示”的根因。不要仅删缩略图掩盖故障。实现同源鉴权截图查看器、加载/失败/重试、适应窗口与原尺寸/缩放、资源版本变化后的错误状态恢复；无截图也有诚实提示。

按规格重构 Logo 卡片，增加紧凑/标准/宽松和尺寸微调，按实际容器宽度调整 Logo、标题、摘要、标签和间距，不用 transform:scale；始终保留名称、地址、查看截图与打开操作。偏好按当前 origin+用户隔离保存在本机，拖动不写 Site、不重复拉取网站库/截图。保留直接入库、分类备注、Logo、旧队列与权限隔离。

按第 7 节补回归与真实 Edge 检查，截图故障验证要包含刷新后、新图替换后和失败重试。完成后更新当前 4173 独立测试环境，保留现有账号收藏，不部署云端。若改扩展源码，使用新补丁版本并重建 ZIP/哈希/站内下载；如仅改网页，不为凑版本改扩展。更新项目文档，报告结果及剩余限制。
