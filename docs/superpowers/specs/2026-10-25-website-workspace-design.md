# 私人网站工作台设计规格

日期：2026-10-25（Asia/Shanghai）
状态：用户已授权完整实施；最新指示为先看网站原型。当前进入视觉方向探索，尚未编写应用代码。
范围：多人独立网站库、用途检索、多访问入口、账号说明、浏览器快速收藏。

## 1. 用户确认与设计默认值

### 1.1 用户已确认

- 网站部署在云端，收入自部署的云端服务、本地服务和常用第三方网站。
- 多人使用，按账号分别管理各自的网站。
- 收藏不能只显示网站名称，需要保留用途，便于忘记名称时找回。
- 在平时使用浏览器时能够快速收藏。
- 导航页记录账号和登录方式；密码由独立密码管理器保存并填充。
- 用户已认可上一轮产品方案，可以推进书面设计。

### 1.2 可调整的默认值

- 中文界面，桌面优先，手机支持搜索、浏览、手工添加和编辑。
- 首版浏览器扩展面向桌面 Chrome 和 Edge，采用 Manifest V3。
- 首版账号采用邀请注册；共享、公开个人主页不进入首版。
- 部署方案为单机 Docker Compose、HTTPS 反向代理及 PostgreSQL。
- 应用建议使用 TypeScript 和 Next.js 构建模块化单体；实现前核对稳定版本并锁定依赖。
- 浏览器收藏扩展和网站共用业务 API；密码库采用网址匹配衔接。
- 云厂商、域名、服务器规格和用户主要浏览器尚未指定，当前没有实际部署配置。

## 2. 问题、目标和首版边界

用户记得网站能做什么，却忘记名称；文件夹和站点标题不足以支持找回。
自部署服务还有不同环境与入口；第三方站点可能有多个账号和登录方式。

首版闭环：导入或收藏 → 补充用途 → 检索和筛选 → 选择访问入口 → 使用正确账号登录。

首版交付：

1. 登录、退出、邀请注册、账号停用、会话撤销与账号恢复流程。
2. 各账号独立的网站、入口、分类、标签、工作集与账号说明。
3. 网站卡片、列表、详情、添加、编辑、置顶、归档、回收站。
4. 中文用途、名称、备注、别名、标签与域名检索。
5. 一个网站对应多个访问入口，并可设置默认入口。
6. 网站关联账号用途、用户名、登录方式及登录入口。
7. 扩展收藏、重复提示、收件箱、断网待同步、账号绑定与凭证撤销。
8. 浏览器 HTML 书签导入，以及本站 JSON 导入导出。
9. 公网元信息异步补充、备份与恢复操作说明。

后续扩展：语义搜索、共享工作集、网页全文存档、服务可用性监控、续费提醒、原生书签自动同步、移动浏览器分享入口。
上述功能不作为首版完成条件。

## 3. 角色与隐私边界

| 角色 | 首版能力 |
| --- | --- |
| 普通用户 | 管理自己的资料、入口、账号说明、分类、标签、工作集和扩展设备 |
| 系统管理员 | 创建邀请、停用或恢复账号、管理恢复请求、查看脱敏运行状态 |
| 收藏扩展 | 以已绑定用户身份新增收藏，查找当前地址的收藏，更新允许的收藏字段 |

- 业务 API 不提供管理员任意查看其他用户收藏的入口。
- 管理员角色不隐式绕过收藏归属校验；管理 API 与私人资料 API 分离。
- 本方案中的网站资料并非端到端加密，拥有数据库或服务器权限的维护者仍可能读取资料。
- 密码、验证码种子、恢复码和 API 密钥不属于普通网站备注字段。
- 账号字段属于用户私有资料，列表默认不展示完整邮箱或用户名。

### 4.1 页面清单

| 全部网站 | 分类、标签、类型、访问条件筛选，排序与批量归档 |
| 我的部署 | 筛选自部署服务，突出环境和多入口 |

| 工作集 | 按任务组织网站引用，支持手动排序 |
| 网站详情 | 用途、个人备注、标签、所有入口、账号说明、编辑历史时间 |
| 归档与回收站 | 归档查询、恢复、单项永久删除与确认 |
| 导入导出 | 文件校验、预览、重复处理、导入结果和用户资料导出 |
| 设置 | 分类标签管理、扩展设备、会话、个人账号与显示偏好 |
| 系统管理 | 邀请、账号状态、恢复请求和脱敏运维信息 |

### 4.2 首页行为

- 桌面端左侧导航，顶部搜索，主区置顶与最近使用；窄屏导航折叠。
- 卡片优先显示名称、最多两行用途、少量标签、访问条件和主要动作。
- 完整备注和账号放在详情中，避免首页暴露账号资料或形成信息墙。
- 置顶位置固定，由用户排序；最近使用独立展示。
- 最近使用仅统计从本站发起的打开操作，不声称掌握用户所有浏览历史。
- 页面内 Ctrl/Cmd+K 聚焦搜索，方向键选择，Enter 打开默认入口。
- 支持键盘操作、可见焦点、表单标签、错误关联和移动端可触达操作。

## 5. 领域模型

所有用户拥有的实体均携带 owner_id；关联关系需验证同一 owner_id。
用户归属从已验证会话或扩展凭证获得，客户端提交的归属字段不参与授权。

| 实体 | 主要字段 | 约束与含义 |
| --- | --- | --- |
| User | id、email、password_hash、role、status | 平台登录凭据采用成熟认证库处理 |
| Invite | token_hash、expires_at、used_at、created_by | 有效期、一次性激活，注册成功后失效 |
| Session | user_id、expires_at、revoked_at | 退出、停用、改密和撤销时按策略失效 |
| Site | owner_id、name、purpose、notes、aliases、kind、category_id、is_pinned、is_inbox、archived_at、deleted_at | 网站资料主体；kind 区分自部署与第三方 |
| Endpoint | owner_id、site_id、label、url、environment、access_scope、device_hint、is_default | 每个活动网站至少有一个入口且只有一个默认入口 |
| AccountNote | owner_id、site_id、endpoint_id、label、username、login_method、login_url、notes | 可关联网站整体或其特定入口；不包含密码字段 |
| Category | owner_id、name、sort_order | 首版使用单层分类，每个网站至多一个分类 |
| Tag / SiteTag | owner_id、name；site_id、tag_id | 同用户内标签名规范化去重 |
| Collection / CollectionSite | owner_id、name；site_id、sort_order | 工作集引用网站，不复制网站资料 |
| Visit | owner_id、site_id、endpoint_id、opened_at | 仅记录从本站触发的打开 |
| ExtensionDevice | owner_id、name、token_hash、expires_at、revoked_at | 每设备可撤销、限定作用域的凭证 |
| CaptureReceipt | owner_id、device_id、client_capture_id、site_id | 唯一约束防止同一次收藏重试产生多条资料 |
| ImportJob | owner_id、format、status、counts、expires_at | 预览和提交均验证归属与文件限制 |

purpose 为个人认可的用途说明；抓取简介单独保留，不覆盖个人内容。
aliases 使用多个别名；同一站点不同路径可能是独立页面，不按域名强制合并。
归档隐藏于常规浏览且可通过筛选找回；回收站内容默认不进入搜索。
删除网站及关联资料应在事务中执行；永久删除需要明确确认，备份按保留策略自然到期。

## 6. 搜索与组织规则

- 查询范围先限定当前用户，再进行匹配与排序。
- 首版检索字段：名称、用途、个人备注、别名、标签和入口域名。
- 用户名和账号备注不混入全局网站搜索结果，账号在网站详情中查询。
- 输入进行空白及大小写规范化；支持中文短语包含匹配和多个关键词组合。
- 排序优先名称或别名精确匹配，其次名称和用途，再到标签、域名与备注。
- 结果显示匹配摘要；同分时参考用户置顶和从本站打开的时间。
- 搜索和列表使用相同的分类、标签、网站类型及访问条件筛选语义。
- 搜索框清空后恢复当前视图；空结果提供修改关键词或新建网站动作。
- 首版不承诺任意自然语言理解或拼音检索；后续按真实使用需要增加。
- 工作集删除只移除组合关系；网站仍保留在个人库中。

## 7. 多访问入口和账号说明

- 支持 http 与 https 入口；拒绝 javascript、data 等可执行地址方案。
- 入口环境包括正式、测试、开发和自定义文本；访问范围包括公网、局域网、本机、需 VPN。
- 用户显式选择默认入口，不依赖云端自动推断用户所在网络。
- localhost 与回环地址指向点击时的设备；界面显示设备提示与访问条件。
- 首版入口可用性显示未检测，不使用未经检测的在线绿点。
- 页面通过浏览器顶层导航打开入口，不通过导航服务器代理本地服务。
- 账号说明可记录日常、管理或测试用途，支持同一网站多个账号。
- 首版密码联动采用打开正确网址后由密码管理器识别并填充的流程。
- 网站不读取密码管理器保险库、不保存解锁凭证，不提供跨站自动登录承诺。

## 8. 收藏扩展

### 8.1 初次连接与凭证

1. 用户在已登录网站中为当前扩展设备生成一次性配对码，有效期 5 分钟。
2. 用户在扩展设置中输入本站 HTTPS 地址和配对码。
3. 配对成功后扩展得到仅供该设备使用的访问凭证，并展示账号与服务器。
4. 凭证默认有效 30 天；过期或撤销后要求重新连接，保留原账号的待同步资料。
5. 服务器保存凭证散列，不在普通日志中输出配对码或访问凭证。

### 8.2 收藏流程

1. 点击扩展或自定义快捷键，读取当前网址、标题和图标信息。
2. 弹窗显示当前账号、已收藏状态、名称与一句话用途输入框。
3. 用途为空时可以保存到收件箱；用户可手动选择分类与标签。
4. 点击保存后生成 client_capture_id，提交当前用户的收藏请求。
5. 收到服务端确认才展示已收藏，保存后停留在原网页。

### 8.3 重复、重试与账户切换

- 同一用户已保存相同地址时，展示已有条目，允许打开或更新。
- 地址规范化仅处理明确等价部分；首版保留查询参数和片段，避免破坏页面或哈希路由。
- 用户可选择网站首页或当前具体页面，多个页面不按同域名强制合并。
- 请求超时或网络断开显示待同步；按退避策略重试，支持手动重试。
- 同次请求依赖 CaptureReceipt 去重；同地址新增通过事务避免并发重复。
- 待同步条目绑定服务器、原账号和设备，切换账号后绝不转投新账号。
- 失效凭证暂停同步；重新连接原账号后可恢复，用户也可删除本地待同步内容。
- 不能读取的浏览器内部页面显示明确说明，保留手动粘贴网址的路径。

### 8.4 权限和采集边界

- 当前标签页采用 activeTab，按需申请 scripting、storage 与本站服务地址权限。
- 默认不上传网页全文、Cookies、表单内容或浏览历史；元信息失败仍可保存网址。
- URL 可能包含一次性令牌等敏感内容，弹窗允许查看和修正保存地址。
- 首版不接管原生星标或 Ctrl+D，不申请原生书签全量读取权限。
- 手机端首版通过网页手工添加网址，不承诺桌面扩展在手机浏览器运行。

## 9. 导入、导出和收件箱

- HTML 导入支持通用 Netscape 书签格式；JSON 使用本站带版本号的结构。
- 文件先限制大小和条数，再解析、清理危险文本并生成预览。
- 原文件夹路径保留为导入来源线索，新增条目默认进入收件箱。
- 预览区分新增、已存在、文件内重复和无效地址；默认跳过已有记录。
- 覆盖个人内容必须显式选择；默认保留已有用途、备注、分类及入口。
- 提交使用预览时的原用户身份，重复提交不产生重复导入。
- 导出为当前用户的完整网站资料，包含入口、分类、标签、工作集和账号说明。
- 导出前提示其中可能含用户名和个人备注，文件不含平台密码散列、会话或扩展凭证。
- 收件箱可搜索、批量分类或归档，整理后显式移出收件箱。

## 10. 架构与业务 API

### 10.1 模块化单体

Web 与扩展 → 认证和授权层 → 网站、组织、收藏、导入等业务模块 → PostgreSQL。
公开网页元信息由异步任务处理，失败不回滚用户收藏。
复杂系统组件在出现实际容量需求前不引入；首版不依赖向量库或独立搜索服务。

模块边界：

| 模块 | 职责 | 关键依赖 |
| --- | --- | --- |
| identity | 登录、邀请、恢复、会话和管理角色 | 认证库、数据库 |
| library | 网站、入口、账号说明、归档、回收站 | identity、数据库 |
| organization | 分类、标签、工作集和排序 | library、数据库 |
| discovery | 当前用户检索、筛选、最近打开 | library、organization |
| capture | 扩展配对、收藏、去重、重试回执 | identity、library |
| transfer | 导入预览、提交与导出 | library、organization |
| enrichment | 公网元信息提取、限制与失败重试 | library、受限网络客户端 |
| operations | 管理、脱敏日志、备份与恢复说明 | identity、部署环境 |

### 10.2 拟定 API 资源

- /api/sites、/api/sites/:id、/api/sites/:id/endpoints、/api/sites/:id/accounts。
- /api/categories、/api/tags、/api/collections、/api/search、/api/visits。
- /api/extension/pair、/api/extension/captures、/api/extension/lookup。
- /api/extension/devices、/api/imports/preview、/api/imports/:id/commit、/api/exports。
- /api/admin/invites、/api/admin/users；认证接口遵循选定认证库的约定。

API 采用有界分页、输入长度限制、明确校验错误、幂等收藏和稳定错误码。
详情不存在或不属于当前用户统一返回资源不存在，避免通过编号枚举其他用户记录。
鉴权失败、凭证过期、验证失败、重复冲突、限流和服务器错误应有不同的可处理响应。

## 11. 安全、恢复与运行

- HTTP 会话 Cookie 使用 HttpOnly、Secure 和适当 SameSite；写操作校验 CSRF 和请求来源。
- 全部对象访问验证 owner_id，包括嵌套关联、导入任务、批量操作和账号说明。
- 浏览器来源限制仅作为补充，不能代替扩展凭证和用户归属校验。
- 登录、邀请、配对和收藏接口限流；停用用户后会话和扩展凭证失效。
- 名称、备注、导入内容和抓取简介均视为不可信文本，页面输出进行安全转义。
- 首版富文本采用纯文本显示；若后续支持 Markdown，需独立清洗策略。
- 公网抓取限制协议、端口、超时、响应大小和重定向次数；每跳重新校验 DNS 解析和目标地址。
- 阻断私网、回环、链路本地、云元数据等目标，并在网络出口层补充限制，覆盖 DNS 重绑定风险。
- 不向抓取目标发送用户 Cookie、平台认证头或扩展凭证；首版不自动抓取本地入口。
- 普通日志隐藏查询参数、账号内容和完整私人网址；审计关注事件、用户 ID 与结果。
- 服务端密钥通过部署环境配置；私人数据备份加密并保存在独立位置。
- 默认每日备份，保留 7 个日备份和 4 个周备份；首次上线前执行一次独立恢复验证。
- 平台账号恢复采用已验证身份后的短时一次性链接；未配置邮件时由管理员核验身份后通过可信渠道交付。
- 恢复令牌使用散列保存，有效期 15 分钟，使用后失效；改密撤销旧会话和扩展凭证。
- 管理员恢复通过服务器运维命令执行并留审计事件，不设置公开后门或预置通用密码。
- 首版依赖成熟认证实现，安全检查中覆盖强密码、暴力尝试限制、会话轮换与恢复路径。

## 12. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 账号隔离 | 用户 A 无法通过详情、搜索、修改、导出、批量或嵌套接口取得或操作 B 的资料 |

## 15. 完整实施授权与原型优先级

用户在阅读规格后提出“这个方案以最完整的形态进行实施”，随后明确“先出网站原型我看看”。
完整产品目标保留，当前优先交付视觉原型，选择后实现使用示例数据的可交互网页。

- 原型展示用途检索、卡片或列表、入口选择、收藏和账号说明，不连接真实密码库。
- 多人身份和资料隔离仍是正式系统需求；原型中的用户头像不代表已实现登录。
- 共享工作集、语义搜索、网页存档、公开入口监控、续费提醒、原生书签同步和移动分享纳入完整路线。
- 后续实现需为共享分别设计资料和账号说明的授权，不默认公开私人账号内容。
- AI 语义能力、邮件、服务器和域名等外部依赖，在相关实现与接入前解决凭据或运行条件。
- 本次视觉探索不需要 OpenAI API 凭据，也不调用付费应用 API；使用内置图像生成工具。
- 原型视觉由三个不同的首页设计方向开始，展示后等待用户选择；不将静态图声称为可点击原型。
