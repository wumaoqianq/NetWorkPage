# 需求修订：少操作收藏、紧凑工作台与统一反馈

日期：2026-11-16，Asia/Shanghai。状态：用户反馈后的实施规格，已实现并完成本机自动化验证；实体扩展验收仍需执行。

本文件优先于 2026-11-15 扩展与卡片设计中与之冲突的产品行为。用户目标是节省精力和时间：用户负责选择分类、填写个人备注，软件负责采集与呈现。保留旧方案的身份隔离、网络边界、幂等、版本控制及备份安全要求。不要把旧版截图逐次确认、用途决定收件箱、首页只看置顶等规则继续作为本轮验收标准。

## 1. 已确认偏差与实际原因

| 用户反馈 | 当前代码情况 | 本轮目标 |
| --- | --- | --- |
| 插件应直接选择用户分类、写备注 | 分类藏在“更多整理”；只有用途，没有 notes 输入/协议字段 | 主界面直接显示分类、个人备注；分类来自当前用户 |
| 图、图标等应自动获取 | 图片要手动添加/裁切/确认；SiteIcon 主要匹配内置资源名 | 用户点击收藏时自动准备截图、简介和真实网站图标，失败降级不阻塞 |
| 卡片太大 | 280px 最小宽、全宽 16:9 图、重复用途/标签/大按钮占据大量纵向空间 | 默认紧凑卡片，截图只做小缩略图；大图放详情 |
| 提示反馈不足 | 零散 toast；例如分类新增/删除缺成功提示，截图/文字局部成功不直观 | 统一按钮状态、就近反馈与结果提示，可恢复错误有下一步 |
| 收藏后还要整理 | v2 根据用途/分类决定 inbox；home 无搜索时排除未置顶 | 普通收藏直接入库，未分类也可首页看到；收件箱必须用户主动选择 |

定位入口：extension/popup.html、popup.js、popup-form.js、page-data.js、queue.js；server/workspace/extension_v2.py、extension.py、validation.py；prototype/src/model.js、components/SiteCard.jsx、SiteIcon.jsx、OrganizationSettings.jsx、useWorkspace.js。

## 2. 插件默认界面：先完成收藏

弹窗宽约 380px。主界面只保留：

```text
[Logo] 网站工作台            已连接 · 设置

[图标] 当前网站名称
       example.com/path       修改资料 ▾

分类     [选择分类 / 未分类                 ▾]
         管理分类 ↗           刷新分类
我的备注 [记下使用经验、用途或提醒，选填       ]
         [                                  ]

✓ 简介已获取  ✓ 图标已获取  ◌ 正在准备页面预览
缩略预览 [小图]      自动采集设置 ▾

[ 收藏到网站库                            ]
保存后直接出现在工作台，无需再次整理
```

“修改资料”折叠区才显示名称、地址、简介、访问条件、标签/工作集、旧用途字段。保留高级能力，不要求新用户理解“用途/简介/备注”三个输入的区别。主界面“我的备注”明确写入 `notes`，不能偷换成 purpose。

分类选项与工作台自定义分类完全一致；空分类叫“未分类”，不叫“待整理”。不自动猜分类；可按用户主动开启的“记住上次分类”保留当前服务器+用户的选择，默认关闭，避免误分。分类载入失败仍允许未分类收藏；已有缓存标注“离线分类”，且不静默清空已选项。手动刷新不覆盖当前有效选择；分类被删时就近提示“此分类已删除，请重新选择或使用未分类”。“管理分类”打开工作台对应设置，返回插件可点击刷新，不强制重配对。

备注上限 2000 字，与网页表单一致；提供字数计数，不要求必填，不采集网页内容代替用户备注。提示“请勿填写密码或密钥”放占位/帮助中，不反复弹窗。

## 3. 自动获取的明确行为

### 3.1 时机与首选项

仅由用户点击插件/收藏触发，不监听所有浏览行为。打开插件即并行准备名称、简介、图标、当前可见区截图，不让用户点击“添加截图”。用户收藏动作代表将界面明确展示的采集结果保存到工作台，不另设每次确认/裁切步骤。

首次成功配对后展示一次简短说明：“收藏时自动保存当前页面预览、网站图标和简介；截图可能包含当前登录内容，你可随时关闭。”自动页面预览默认开启，界面可见开关“自动保存页面预览”；每次收藏还可以一键“这次不带截图”。设置按完整服务器 origin+用户隔离，断开/切换时不沿用其他身份偏好。不要设计阻断收藏的首次多步向导或强制隐私弹窗；说明与开关常驻可找到。

默认对隐身/非 HTTP(S) 页禁用截图，沿用导航竞态复核；截图前后 tabId/windowId/URL 必须一致。自动采集失败、超时、拒绝权限时，继续收藏名称地址及用户备注，显示具体降级原因。截图失败不弹出要求用户补拍的必经步骤。

### 3.2 截图语义

默认自动截图是“当前页面预览”，不是网站主页截图。浏览器处于子页或已滚动时不能声称获取到了首页。不得为追求“自动”在后台打开陌生主页、打断当前浏览、滚动页面或运行低内存服务器无头浏览器。

本轮以自动当前页预览满足识别需求：主卡片不突出来源技术细节，详情显示“当前页预览 · 时间”。高级操作可以保留首页确认/更换图，但默认收藏无需进入该流程。用户选“站点首页”时，若仍在子页，只存地址/简介允许的降级值；不要把子页图标之外的子页描述/图片冒充首页。

限制沿用 960×540、200KiB 主图、服务端缩略图、账户配额和离线 Blob 存储。原始截图不永久保存；不读取表单/密码/Cookie，不承诺自动去除图中的隐私。

采集状态各自独立：ready/loading/unavailable/disabled；文案“预览获取失败，仍可收藏”，提供非必需重试。点击收藏时最多等待仍在进行的视觉采集 2 秒；超时后锁定本次提交为纯文字/已有附件，不让迟到回调改变已持久化任务。自动截图须在用户操作的活动页授权仍有效时发起，不能等网络查重完成后再开始。

### 3.3 图标

首选当前 tab 的 favicon 信息/主 frame 的 link rel icon，兼容多个候选；其次读取网站图标的安全回退路径。图标是实际图片，不把任意 URL 写进原 `icon` 内置资源名字段。明确建立 `SiteIconAsset` 或同等受管媒体记录，前端从同源鉴权地址读取。

图标抓取必须使用当前页面已有的临时 origin 授权和有限请求，不能为任意 CDN 新增全站常驻权限；跨源候选无法读取则跳过，展示网站首字母/内置通用图标。页面可能提供 data URL、SVG 或损坏图片，需做实际解码/格式/大小校验，拒绝直接执行 SVG。只接受经过解码重编码的 PNG/WebP，最大 128×128、32KiB；剥离元数据，不保存原始 SVG/HTML。若使用浏览器原生 favicon 读取能力，核实权限并说明其新增范围，不借机读取浏览历史。

禁止由前端直接使用远程 favicon URL，禁止使用 Google 等第三方 favicon 服务代替自动采集，避免打开工作台时泄露用户的网站库。缺图只降级，不要求用户手动上传。独立处理图标和预览的上传、重试、配额、备份/GC；选择一个图的失败不能导致另外一个结果丢失。

### 3.4 标题和简介

沿用页面 title 与元描述白名单自动读取，迟到响应不覆盖用户已修改内容。简介缺失显示“未提供简介”，不制造 AI 文案。当前页和首页资料不能混用。用户默认无需填写标题、简介、图标和截图；“修改资料”中可覆盖文字或关闭本次图片。

## 4. 收藏直接入库、首页立即可见

统一约定：`inbox = later === true`，不再根据备注、用途、分类、工作集是否为空自动推导。默认 later=false，主操作名“收藏到网站库”；“暂存收件箱，稍后整理”只在高级操作中可选，默认关闭。

首页默认展示全部有效收藏，置顶优先、其次最近收藏（以 createdAt 降序、稳定 ID 作为次序）；取消 `home && !pinned` 的排除规则。空白搜索与有搜索时的来源范围保持一致。置顶是排序优先，不是收藏被首页看到的门槛。其他分类、归档、回收站仍按现有条件过滤。

收件箱不是必须经过的审核站：普通收藏立即在“全部网站”、用户分类和首页出现；收件箱中的条目也已在库中，只是用户主动标记稍后整理，不应复制成第二条记录。归档/删除另有明确状态。

同步响应给出实际保存位置：`已收藏到「设计工具」` 或 `已收藏到网站库 · 未分类`；一张图片失败提示“网站已入库，预览稍后重试”，不能只显示“等待处理”。离线真实提示“已存本地，联网后自动入库”，不宣称服务器已保存。

网页从后台恢复焦点/可见时自动刷新；可见页面每 30 秒检查轻量变更版本，不重复全量加载/图片请求，无变更不改状态。插件点击“在工作台查看”应指向刚收藏网站的详情或可定位的卡片，不能只打开一个仍然看不到新收藏的首页。需设计可登录后恢复的 `site` 深链，严格按当前用户校验，不把账号/备注/token 写进 URL。

历史收件箱记录不擅自批量修改：首页修复后仍可看见；提供可选“将现有收件箱全部整理完成”，显示数量并确认，服务端版本/归属检查后清除 inbox，不改变分类和备注。不能在迁移时抹除用户过去主动设置的 later。

## 5. 重复收藏与个人备注的接口契约

v2 新增可选 `notes` 字段，2000 字上限；旧客户端不传时保持原语义。新收藏保存 notes；用户不写不造成错误。不扩大现有 Bearer 对私人资料的读取权限：lookup 默认不返回已有 notes、账号说明或私有图片。

重复收藏时显示“已收藏到…”，默认不覆盖已有资料。新写备注由用户选择“追加这段备注”，服务端按本次唯一 capture ID 幂等追加并标记追加时间；不要在客户端先读取所有旧备注再拼接。若总长度超过网站备注限制，返回明确可处理错误，不能静默截断旧内容。清空/替换旧 notes 只在网页完整编辑中完成。

分类变更提供清晰动作“移动到所选分类”，使用 expectedVersion，未确认不改变原分类。截图/图标允许自动获取，但已有收藏的图片替换仍需用户点击“更新预览和图标”，不在仅打开弹窗时自动改服务端。无变化点击“已收藏”不产生新条目。

已有规范要求的新 UUID、字段白名单、同账号离线恢复、版本冲突保留输入继续有效。自动素材只随实际提交产生附件；未收藏就关闭弹窗时不上传，图片草稿不永久残留。

新增图标能力需独立 capability 标识并兼容旧服务端；后端不支持时纯文字/已有预览继续保存。notes 不应静默丢弃；若后端版本不支持 notes，明确要求更新本地服务，保留草稿。不把新 payload 塞入旧 captures 触发未知字段错误后仍显示成功。

## 6. 紧凑卡片与信息密度

默认样式替代全宽大截图卡片，不新增一个需要用户自行寻找才能解决臃肿的隐藏模式。

```text
┌───────────────────────────────────────┐
│ [32px 图标] 网站名称              ⋯    │
│             example.com/path          │
│ 简介或备注摘要，两行以内……     [小预览] │
│ [自定义分类] [标签 +2]        打开 ↗   │
└───────────────────────────────────────┘
```

卡片目标宽 240–300px、常规高 160–180px；不因缺图保留一整块大占位。桌面 1280px（扣除侧栏）约 3 列，1440px 约 4 列，1920px 约 5 列，以可用宽度为准；gap 12px。移动端单列卡片仍保持紧凑，不能恢复成全宽大图。

图标 32px；预览约 80×45 或 88×50，放正文右侧，仅在有图时展示；名称一行截断，地址一行，摘要两行；正文 padding 14px。个人备注优先摘要（标“备注”），无备注取简介，再无内容显示“暂无简介”。不要同时强制展示简介、用途、备注三块文字。全文在详情查看，搜索仍覆盖全部字段。

底部使用 32px 高操作区，移动端操作目标至少 44px；保留清晰的“打开”按钮、点击名称/缩略图进详情、菜单管理，不把整卡做成外链。图标加载失败回退首字母，预览失败不影响打开。复制地址在悬停/焦点时显示，复制成功就近反馈。

取消卡片上占空间的截图日期/来源徽章和重复“详情”按钮；来源、日期和大图放详情。置顶以小图钉显示。列表模式保留更高密度，用户选择可按账号保留，但默认紧凑网格已应足够好用。仍按批次渲染，禁止为全库同时请求图片。

## 7. 统一反馈与设置体验

所有实际写操作必须具备：未提交→执行中（防重复点击）→成功/失败。成功要说清对象和结果；失败保留输入，在原操作附近说明原因及下一步。不能只写 console 或吞掉异常。

| 操作 | 执行中 | 成功 | 失败/下一步 |
| --- | --- | --- | --- |
| 收藏 | “正在保存…” | “已入库 · 分类名”，查看收藏 | 离线保留/重配对/修改失效分类 |
| 分类新增 | 添加按钮 loading | “已添加分类「…」”并显示新项 | 重名或空值在输入下方提示，保留输入 |
| 分类删除 | 确认按钮 disabled | “已删除分类，N 个网站保留在未分类” | 权限/网络错误可重试，不消失确认框 |
| 编辑备注/分类 | 保存中，保留表单 | “修改已保存” | 409 显示重新载入对比，不能静默覆盖 |
| 配对 | 正在连接，明确服务器 | “已连接到…”，设备列表出现 | 过期重新生成；权限拒绝提供重试 |
| 自动素材 | 每项独立状态，不锁收藏按钮 | “图标/预览已就绪” | “获取失败，仍可收藏”，可重试 |
| 截图上传 | “网站已入库，预览同步中” | “预览已保存” | 保留原图，自动重试或移除任务 |
| 复制 | 无需全局 loading | 按钮临时“已复制” | 失败显示可手动选择的内容 |
| 撤销设备 | 明确二次确认 | “已撤销，待同步任务暂停” | 可重试，不显示已断开 |
| 下载 | 提示浏览器开始下载 | “下载已开始，接下来解压并加载” | 不把收到下载响应当安装成功 |

全站 toast 统一右下角，成功 4 秒，普通信息 6 秒；错误除 toast 外保留就近提示，不要求用户在几秒内读完。通知使用 aria-live，字段错误 role=alert；不靠颜色表达，聚焦错误字段。设置页顶部说明“操作后即时保存”或“修改后点保存”，不让用户猜。

插件使用固定底部反馈条：显示“将保存到哪个服务器/账号/分类”、保存状态和下一步。网络错误不覆盖用户正在阅读的字段错误；后台状态更新不每秒刷同一条 toast。新增“撤销”仅对可恢复操作（归档/回收站/移动分类）提供；永久删除与撤销设备不伪造可撤回能力。

## 8. Logo 与接入

已提供原创矢量设计：`docs/brand/workspace-mark.svg`、`workspace-mark-mono.svg`、`workspace-logo.svg`。概念为“网站卡片收拢成书签”，沿用绿色体系；名称继续用网站工作台。详细尺寸与净空见 docs/brand/README.md。

开发统一接入侧栏、登录/初始化页、连接状态、favicon、插件 popup/options 与 16/32/48/128 PNG，替代花括号和旧通用书签标志。不要只改网页而让下载插件继续用旧 Logo。SVG 保留为源文件，PNG 应由同一源可重复生成，16px 可简化短线。

## 9. 完成与验证标准

1. 工作台自定义分类后，插件可刷新并选中；只选分类+写备注+点收藏即可完成，标题/简介/图标/预览不要求人工填写。
2. 选择分类与不选择分类各收藏一次，都直接在首页和全部网站出现；没有用途/备注也不自动进收件箱。主动稍后整理才有 inbox=true。
3. 捕获导航/切 tab、禁止页、无图标、跨域图标、断网、权限失败和图片超限均可完成文字收藏，并说明降级。
4. 备注保存到 notes，网页详情/搜索可用；普通设备 lookup 不泄露已有私密 notes；重复追加幂等且不覆盖旧内容。
5. 已打开的工作台无需人工刷新即可发现新收藏；“查看收藏”能准确定位；轮询不造成图片重载或丢失正在编辑的表单。
6. 独立合成数据准备 30/100/1000 条，记录 1280/1440/1920px 首屏卡片数和实际高度；360px、键盘、200%缩放可用。不得只用两张卡片声称密度问题解决。
7. 对设置各项逐一测试成功/失败反馈、重复点击、保留输入；需要真实 Chrome/Edge 验证 activeTab 截图和图标权限，替身不代替真实浏览器。
8. 图片/图标越权、伪类型、配额、备份恢复、队列迁移和旧协议兼容回归；保留之前三个修复，不能重新引入任务丢失和版本竞态。
