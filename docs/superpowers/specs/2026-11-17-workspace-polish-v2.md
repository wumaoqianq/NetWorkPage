# 工作台展示优化第二版：宽屏、真实图标与细节一致性

日期：2026-11-17。状态：设计与开发交接，未修改业务代码、用户数据或运行服务。

优先级：本稿覆盖旧规格中固定内容最大宽度、常驻尺寸滑杆、固定用途筛选和过小图标源文件限制；保留普通收藏直接入库、分类/notes、Logo 主体卡片、独立截图查看器、可调尺寸、身份隔离及队列兼容。

## 1. 当前证据与审查边界

本轮在现有本机页面执行：①观察当前页面；②临时设为 1920×1080 并刷新加载最新构建；③截图检查并恢复浏览器原尺寸。未点击写入操作。

现场截图：`.local/design-audit-2026-11-17/current-1920.png`，含当前账号的私有资料，仅本地保留，不打包/上传外部服务。截图分辨率/呈现清晰度受当前浏览器工具影响，本轮不据此判定字体抗锯齿质量。

证据对应问题：

1. 1920 宽屏中主内容起点比侧栏边缘明显内缩；代码 `cards.css` 的 max-width:1440px 与 styles.css 的居中 margin 叠加，造成主区两侧额外留白。不是全局把 padding 设零就能解决。
2. 只有四张收藏卡时，卡片未使用的网格列自然留空；与固定最大宽度的问题要区分。不能为填空把四张卡拉成巨型卡或复制假内容。
3. 截图中 DeepSeek 显示 D。当前图标代码在读取后拒绝大于 200KiB 的图标，使用 createImageBitmap 解码；历史实测记录为该站约 209KB ICO 因限制降级。应以本次真实 HTTP 大小/ICO 帧验证最终原因，不假定所有 D 都是同一原因。
4. 工具栏常驻档位、滑杆、像素值、恢复按钮及网格切换，信息密度比主要内容更高。
5. 当前分类由用户自定义，但快捷筛选依然是写死的三个用途，与分类来源不一致。
6. 部分信息/未分类/无截图使用很浅灰色，存在可读性风险；需测色值和键盘/缩放，不凭截图宣称已符合无障碍标准。

## 2. 视觉方向

保留浅色侧栏、白色主区和绿色强调，不更换 Logo、不增加装饰插画、大渐变或营销式仪表盘。主体验像一个随手可用的网站书架：进入即看到收藏，能快速识别、搜索、打开。

主层级：导航 → 当前页面标题和数量 → 搜索 → 精简工具栏 → 收藏卡片。正文不堆叠欢迎语、大标题、口号与重复说明。页头改为“我的工作台”，副标题“共 N 个网站 · 最近更新…”（真实数据可计算时才显示时间）；搜索占位“搜索名称、简介、备注或标签”。保留“收藏网站”唯一主要绿色按钮。

## 3. 宽屏布局：利用空间而非放大内容

### 3.1 页面骨架

桌面侧栏默认 232px，可折叠到 72px 图标栏；宽度 <1100px 默认折叠，<768px 改抽屉。用户明确选择展开/折叠可按当前 origin+账号保留，移动端抽屉状态不作为桌面偏好。

主内容 width:100%、min-width:0，取消 1440/1550px 的工作台级居中最大宽度；以侧栏占位后剩余宽度计算。左右 padding：<768 为16px，768–1599 为24px，≥1600 为28px。顶部栏、标题、搜索、工具栏、网格与页脚使用同一个内容轨道，两边对齐。

宽屏不要居中摆一条窄内容岛。对正文说明、设置表单和详情阅读区仍保留局部阅读宽度，不把长文字横跨 2000px。超宽显示器也通过增加卡片列数利用空间，不无限放大单卡字号和图标。

### 3.2 网格算法与现有尺寸偏好

保留紧凑220、标准260、宽松320px 的目标宽度及200–340px微调。目标宽度是期望值，不是每张卡死锁的像素尺寸。

以可用网格宽 W、间距 g（紧凑12，其余16）、目标 t 计算：候选列数取 (W+g)/(t+g) 的向下、向上取整，分别计算实际宽 (W-(n-1)g)/n；优先选择实际宽与 t 最接近且位于200–340px的列数。无有效候选时单列/按窄屏实际宽处理；标准目标不应因 floor 计算留下过宽卡片。完整行均分可用宽度，最后一行保持同样列宽且左对齐，不用 auto-fit 拉伸最后几张。

示例（非所有屏幕保证，均按232px侧栏、指定padding、标准260px、gap16）：

| 视口 | 内容宽度 W | 预期列数/卡宽 |
| --- | --- | --- |
| 1440 | 1160 | 4列，约278px |
| 1920 | 1632 | 6列，约259px |
| 2560 | 2272 | 8列，约270px |

侧栏折叠后实时重新计算；不得把上述列数写成媒体查询硬编码。少于一行收藏时保持正常卡片大小，右侧空余是数据不足，不放“推荐站点”等未经用户收藏的内容凑数。无最近访问时整个最近访问区隐藏，不显示横跨页面的空灰条。

## 4. 卡片视觉细化

保留按实际卡宽的小/中/大信息策略与截图按钮；标准档卡高目标约200px，当前正常能力不因美化退回大图卡。Logo 视觉框标准48px、大档64px、小档36px，框内图形留10%安全边距；图片contain，不把非方形logo强裁成方形，不以工作台品牌冒充站点logo。

标题标准15px/22px、深色半粗，名称优先易识别；短名称不凭空扩写，长名称最多两行（小档一行）。地址12px/18px，仅显示主机/可容纳路径，不显示query/hash。摘要13px/20px，个人备注优先、简介次之；有备注时小“备注”标记，避免让测试时间戳/长备注占据所有视觉重点。

卡片内部统一垂直节奏：Logo → 名称间8px，名称→地址4px，摘要6px，分类8px，footer8px；同档同行对齐。隐藏某段文字时相邻间距合并，不留下空行。分类用浅绿底/深绿文字，标签用中性底，置顶图钉小且不遮Logo；“查看截图”为次操作，“打开”为主要文本操作。

菜单触发器默认可见的低对比，hover/focus提高对比；不要只在hover时出现而让触屏用户找不到。复制地址按钮预留稳定位置，显示时不挤动域名；成功2秒提示，失败提供手动复制途径。字体优先系统中文栈，去掉页面对 Google Fonts 外部请求的硬依赖，避免国内网络拖慢首屏和字体跳变。

## 5. 真实网站Logo：解决 D，不是画一个鲸鱼

### 5.1 采集来源与ICO兼容

首先保留用户明确自定义图标，其次有效的私有受管网站图标，再考虑合规的站点候选；字母是最后回退。不得通过名称包含deepseek便套鲸鱼，必须按真实归属host判断（不要把deepseek.example.com误认成官网）。

候选来源：当前页已解析的 favicon、页面 rel icon / apple-touch-icon 中适合的栅格候选、同源/favicon.ico。优先同源有效128/64/48/32px，ICO中选择合适帧而非盲取最大帧；多尺寸ICO整体文件略大不等于最终图标需要大空间。

将源图标读取预算与最终保存预算分开：建议源文件最多1MiB、累计候选最多2MiB、最多4个候选、总墙钟预算5秒；流式读取时超过上限立即取消，不能先无界下载再 blob.size 判断。最终图片仍重编码为≤128×128、≤32KiB WebP/PNG；像素解码上限2百万、元数据剥离，图标不执行脚本。

验证目标浏览器对ICO的实际解码支持。若createImageBitmap不能可靠解ICO，使用经过审查的本地解码方案选择ICO的PNG/BMP帧，或利用已有安全服务端能力在公网边界内抓取/解码栅格；优先最小改动。后端方案不得把设备可见内网地址带入服务器请求；私网仍由用户动作下客户端处理。

当前禁止原始SVG直接进入媒体的边界保留；SVG-only站点有安全栅格化能力之前诚实降级，不能为追求图标覆盖率允许未经净化的任意SVG执行。跨源CDN图标缺授权时不申请全站权限，不发Cookie，不通过第三方图标聚合服务绕过。候选无法取用时说明原因。

### 5.2 历史缺图修复

修复采集并不自动修好已入库的D。提供卡片菜单“更新网站图标”和设置→资料维护中的“修复缺失图标”，显示数量与预览结果，用户主动触发；只处理缺图/错误项，不覆盖自定义图标或已确认素材。

可采用带SSRF防护的公开favicon刷新或插件批次方案，由实施agent依据现有能力确定并说明。若只能通过插件，请直接引导打开该站并点击“更新图标”，不能伪造后台修复成功。更新Logo与更新截图分开，避免只想换图标却覆盖原截图。后台批量任务必须显式启动、可停止、串行限量、配额和版本保护，不为每个卡片自动发网外请求。

可选提供自定义本地PNG/WebP上传用于无法自动解析的网站，放高级选项，非默认必经路径。用户上传的主图标标为自定义，后续自动刷新不覆盖。

### 5.3 状态与回退

区分pending、ready、missing、failed、custom状态；卡片pending短暂显示中性骨架，missing/failed显示字母，不常驻大红警告。详情提供“图标未获取：文件格式/大小/权限/网络原因”，有明确重试/更新操作。字母旁无需逐卡写“失败”，但菜单不能让用户误以为D就是官网logo。

图片URL/revision变化时重置失败标记；旧失败事件不能掩盖新图。已成功图标离线可继续按现有授权缓存策略展示（不泄露到其他账号）；不能为了减请求改公开媒体链接。DeepSeek验收需实际显示来自官网候选的鲸鱼图标，报告源host、类型、输入字节、选帧和最终输出，不以截图里“有图片元素”替代正确品牌图形验收。

## 6. 搜索、筛选与工具栏

移除硬编码“图片处理/开发部署/效率工具”。主工具栏显示“全部”和当前用户有实际收藏的常用分类，最多5个，余下进入“更多分类”；分类集合与侧栏同源，重命名/删除实时一致。筛选计数根据真实可见范围，搜索保持全库匹配，不受当前渲染40张限制。

默认工具栏右侧只展示“排序：置顶优先”“显示设置”“网格/列表”。卡片档位、微调滑杆、恢复默认、侧栏/显示密度集中到“显示设置”popover，不一直占主页面。Popover可键盘操作，改变立即预览，关闭保留。筛选/排序改变保留尺寸偏好，尺寸改变保留搜索和滚动位置。

搜索框宽度随内容展开，内部文字可读区保留最大约900px但输入背景与工具栏对齐；不额外创建双边内缩的第三条轨道。搜索有结果显示“N个结果”，无结果显示当前查询和“清空筛选”；Escape清输入但不关闭正在编辑的模态框（顶层弹窗优先）。首次空库直接说明扩展收藏路径，正常非空状态不反复展示新手教学。

## 7. 全站细节清单

- 侧栏分类支持长名省略与完整可访问名称、分类计数，不因无限分类挤掉账户/设置；分类区独立滚动。折叠栏保留tooltip和aria-label，当前选中不用仅颜色表达。
- 最近访问仅有真实记录时显示，最多一行；不复制主网格里所有卡片造成重复信息。页脚弱化为内容流末尾，不硬贴卡片下一行创造粗横条。
- 设置从一个清晰入口进入：资料、分类、扩展、账号等标题一致；配对码倒计时、复制成功、设备到期状态就近显示，不让重要错误只闪toast。
- 加载只替换正在变化的区域；首次库载入使用对应密度骨架，后台刷新不整页闪白。图片失败、暂无截图、离线和会话失效分别反馈。
- 详情、截图查看器及设置弹层均遵循dialogStack；标题/关闭位置一致，长内容内部滚动，焦点返回触发按钮。打开站点不会误触截图/卡片菜单。
- 颜色token统一：正文至少4.5:1、较大文字和可识别UI边界至少按适用标准测量，主要文字不再用过淡灰；hover/focus/disabled/selected有独立状态。200%缩放允许高度增长，不隐藏操作。
- 移动端筛选可横向滚动但有可见边缘提示，不让整页横向滚动；搜索与收藏入口可达。触控按钮44px目标，减少动画且支持prefers-reduced-motion。
- 保留收藏成功、本地排队、素材部分失败的真实状态；视觉优化不改变队列、notes、归属、备份和收藏生命周期。

## 8. 验收与实施交接

先对照现有页面测量实际边距/网格宽，再重构统一布局容器；清理重复CSS覆盖，不能再在文件末尾不断叠max-width。使用30/100条独立合成库+4条少数据场景，验证1440/1920/2560/3440及360/768、侧栏展开/折叠、三档尺寸和200%缩放。宽屏主区只留规定padding，最后一行不拉伸，少数据不补假卡片。

DeepSeek真实官网及另一多帧ICO网站须经过真实扩展采集、私有上传、刷新和Logo查看；覆盖>200KiB但≤1MiB源图、格式错误、超预算、无候选、跨源无权、ICO解码失败、历史缺图修复。验证网络流限额/解码像素预算，不仅改一个常数；最终上传图标仍≤32KiB。

前端截图需同时记录viewport、实际内容宽、padding、列数/卡宽；Logo来源需记录真实类型与大小。带用户私密截图只本地保存，不发布。运行相关前后端/扩展/备份回归，实际改扩展则新补丁版本、ZIP清单哈希与安装运行时同步，防止再次目录新版但后台旧版。

完成后更新现有4173独立环境，保留账号、收藏、配对及队列，不另建空库、不部署云端。交付桌面/手机截图、真实鲸鱼Logo证据、操作反馈、故障恢复、性能与未实测项；不把预设合成图片当自动获取成功。

给新开发agent的任务：按本规格完成展示优化与Logo修复，先读README、prototype/AGENTS.md和最新项目状态。重点不是无限放大卡片，而是统一宽屏轨道、均衡列宽、简化常驻控件、真实图标可靠采集与历史缺图可恢复。沿用现有绿色风格和已验收功能，先修DeepSeek等ICO输入预算/解码链路，再验证旧收藏更新；不得硬编码品牌名配图、引入第三方favicon服务或新增全站常驻权限。完成真实浏览器验证及本机更新，报告结果。
