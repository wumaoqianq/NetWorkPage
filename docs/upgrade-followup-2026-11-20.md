# 2026-11-20 发布与升级续作记录

GitHub 已有 [v1.10.0-rc.10](https://github.com/wumaoqianq/NetWorkPage/releases/tag/v1.10.0-rc.10)，本轮未改已发布资产。DeepSeek Harness 最后的交接明确列出：网页升级面板、迁移中途失败、维护期间真实 Edge 续传、候选新装及稳定版发布尚未完成。之前的线上演练证据仍见 [11-19 验收记录](upgrade-acceptance-2026-11-19.md)。

本轮工作树补齐了管理员「系统更新」、独立 systemd 检查 timer、签名资产本地入口 `--asset-dir`、发布与部署文档。发现 rc.10 自动预检解包会保留归档外层目录，以及升级可能复用未重新验签的已解包目录；当前预检处理归档外层且每次都从签名资产验证。升级按新的备份与维护流程运行，迁移开始就记录需备份回退；无法验证成对恢复时不重新开放写入。安装依赖在维护前完成。

| 验证 | 实际范围 |
| --- | --- |
| rc.10 真实资产 | 用发布时固定的公钥验签、校验服务包及内嵌扩展；在 Windows 从该归档解出的代码向空隔离 SQLite 跑完迁移，Django `check` 通过。未替代 Debian systemd 新装。 |
| 管理员更新面板 | 在隔离 4184 实例用测试管理员登录，通过浏览器看到当前版、模拟可用版、检查时间和最近回退。隔离 API 复核普通用户 403、未登录 401，稳定轨道不会读到预发布轨道的缓存。 |
| 维护期间续传 | 启动本机隔离 Waitress/Django 和独立库，扩展真实 HTTP 请求及 Outbox 模块收到 `503` / `Retry-After: 60`，截图和备注留在队列；模拟时钟推进后由新 Outbox 实例续传，数据库恰好新增一条收藏、一次回执、一张截图。这里使用内存 Outbox 存储，未实测实体 Edge alarm 或 IndexedDB 持久化。 |
| 迁移中途失败 | 回归使用真实 SQLite：模拟已提交的数据修改随后迁移失败，确认恢复 SQLite 与媒体后才检查旧版健康并恢复写入。systemd 调用与加密恢复入口使用隔离替身；未替代真实 Debian 演练。 |
| 回归 | Django 201 项、前端 57 项、Sites 4 项、扩展 168 项、运维脚本 35 项，生产前端构建及迁移无漂移。测试构建试签使用临时 QA 密钥，发布用真实扩展 ZIP 字节未变，候选测试包不得上传 GitHub。 |

下一门槛：在独立 Debian 环境完成真实 systemd 新装、带数据新路径升级、迁移中断与回退；在独立 Edge profile 做维护期弹窗收藏与 alarm 恢复；之后从干净提交正式构建并签名发布。发布说明使用 `--release-version`，不要复用 rc.10 的错误命令。现有 GitHub Release、线上实例和日常 4173 的数据库及配对未改动。
